# Hack RND Autumn 2026 — frontend

Стартовый проект: Next.js App Router, TypeScript, Tailwind CSS, SASS Modules, Axios, Redux и Redux Toolkit.

## Запуск

Используйте Node.js 24 LTS и npm.

```bash
npm ci
cp .env.example .env.local
npm run dev
```

Приложение доступно по адресу http://localhost:3000. На главной странице под общим хедером расположен финансовый дашборд.
Перед подключением API укажите его адрес в `NEXT_PUBLIC_API_URL` в `.env.local`. Переменные с префиксом `NEXT_PUBLIC_` доступны браузеру: секреты в них не хранятся.

## Проверки

```bash
npm test
npm run typecheck
npm run lint
npm run build
npm start
```

Сборка и dev-сервер используют Webpack: Turbopack в текущем окружении не может открыть служебный порт для обработки CSS.
ESLint закреплён на версии 9 из-за peer-зависимостей плагинов Next.js; npm отмечает эту ветку ESLint как неподдерживаемую.

## Структура

- `src/app` — общий layout, страницы входа/регистрации/подтверждения/восстановления, главная страница, заготовка `/account` и стили.
- `src/app/global.scss` — SCSS-переменные палитры и типографики, карты `$colors` и `$typography`, длительность transitions `0.3s`. Фон всех страниц — `#EAEAEA`.
- `src/app/base.css` — CSS-вход Tailwind, подключённый один раз в layout.
- `src/store` — фабрика store и клиентский Provider. Бизнес-слайсы добавляются вместе с функциональностью.
- `src/service/api.ts` — общий экземпляр Axios.

Переменные SCSS подключайте в модулях через `@use`. Компонентные стили храните в `style.module.scss`. Уместные анимации добавляются с интерфейсом с учётом `prefers-reduced-motion`.

## Хедер и бренд

`Header` из `src/widgets` принимает `company` с названием компании и необязательный `avatarUrl`. В текущем контракте компании поля аватарки нет; до подключения выбранной компании хедер показывает «Компания» и первую букву по центру аватара. Мобильный макет включается до 480 px включительно. Название и аватар компании объединены в одну ссылку на `/account`, логотип банка ведёт на `/`. На всей площади обеих ссылок используется курсор `pointer`; при наведении прозрачность меняется до 40% за `0.3s`. На страницах авторизации хедер скрыт.

Логотипы Saldo из архива находятся в `public/icons/saldo`, favicon и manifest — в `public/favicons`. Логотип банка вынесен из макетов в `public/icons/bank`. В корневом layout настроены заголовки, описание, ключевые слова и метаданные Open Graph/Twitter.

## Дашборд

На ПК gap между карточками слева — 30 px. Текст загрузки использует общий `LoadingText`: три точки появляются с ускорением без изменения ширины строки.

Главная повторяет светлый макет `дашборды.svg`: баланс, ситуация и предупреждения слева, график справа. На узком экране первым идёт график, затем карточки одной колонкой. Данные первой компании, датированный остаток и прогноз загружаются через сервисы; название компании передаётся хедеру через Redux.

График построен на [Recharts](https://recharts.github.io/en-US/api/Line/) (MIT). По X — календарные дни, по Y — остаток в рублях; подсказка показывает точную сумму из строки API без потери копеек. Периоды 30/60/90 дней загружают соответствующий горизонт. Линия строится слева направо с ускорением `ease-in` за 900 мс; при уменьшении движения анимация отключается. Transitions элементов интерфейса — 0.3s.

`dashboardService` использует датированный баланс как cutoff, переиспользует актуальный прогноз и опрашивает асинхронную задачу до результата. При смене периода запросы отменяются при уходе со страницы, повторное нажатие во время загрузки блокируется. Нет компании или датированного баланса — показывается состояние недостаточных данных, ошибка — снэкбар и кнопка повтора. Прогнозный кассовый разрыв определяется по `first_gap` ответа API; это не подтверждение фактического неплатежа.

## API-сервисы и уведомления

Типы и 53 операции перенесены из `docs/api/openapi.yaml` ветки `globalarray/docs/cash_flow_architecture`, commit `ed31678`, версия контракта `0.1.0`. Это проект контракта на ревью; готовность backend не подтверждена.

Регистрация дополнена по контракту `origin/main`, commit `482585b`: обязательное `personal_data_consent` и GET `/auth/personal-data-consent`. Всего сервисы содержат 54 операции.

На регистрации два независимых checkbox из UI-кита: обработка персональных данных и ознакомление с политикой конфиденциальности. Gap до текста — 10 px. При установке и снятии отметки проигрывается анимация 0.3s; hover-анимации нет. Документы открываются в отдельных вкладках по `/personal-data-consent` и `/privacy-policy`, доступны до входа и сохраняют общий хедер. Оба checkbox доступны сразу, но изначально не отмечены.

Юридические страницы — серверные компоненты: текст из `src/content/*.json` сразу выводится семантическими HTML-тегами, стили ограничены страницами документов. Загрузка текста через API и отслеживание открытия документа не используются. В регистрации сервер передаёт только версию и SHA-256 согласия. При `CONSENT_DOCUMENT_CHANGED` отметка снимается; для новой редакции нужно обновить страницу и подтвердить согласие снова. В API отправляется отдельное согласие согласно контракту; ознакомление с политикой проверяется формой без дополнительных полей запроса.

Проекты документов адаптированы для Saldo Analytics с реквизитами ПАО КБ «Центр-инвест» из [официального источника банка](https://www.centrinvest.ru/files/about/requisites.pdf). Редакцию `saldo-2026-10-24` и её SHA-256 необходимо согласовать с backend перед подключением реального API.

- `src/interfaces/<категория>/request.ts` и `response.ts` — типы по категориям; общие DTO находятся в `src/interfaces/Entities.ts`, экспорты — в `src/interfaces/index.ts`.
- `src/service/<категория>_service` — сервисы с типизированными параметрами и результатами. Параметры пути передаются как непрозрачные строки и кодируются для URL; запросы принимают необязательный `AbortSignal`.
- `src/service/api.ts` — Axios, cookie-сессии, CSRF перед изменениями, единое уведомление об ошибке. CSRF хранится в памяти, после операций Auth сбрасывается и получается заново перед следующей записью. Запросы автоматически не повторяются.
- Обязательный `idempotency_key` передаётся вызывающим кодом. При повторе одного действия используйте прежний ключ; для нового действия создавайте новый.
- Деньги, версии и даты сохраняют формат API. Суммы в минимальных единицах и версии — строки; `null` сохраняется. Проверки диапазонов, форматов, уникальности и бизнес-ограничений выполняются сервером; TypeScript не заменяет валидацию API.
- Загрузка CSV принимает `File` и собирает `FormData`; multipart boundary устанавливает браузер.
- `showWarningSnackbar`, `showInfoSnackbar`, `showErrorSnackbar`, `showSuccessSnackbar` из `src/helpers/snackbar.ts` показывают уведомления MUI. Отдельные компоненты четырёх вариантов экспортируются из `src/widgets`.
- Ошибки HTTP показывают безопасный `error.message` из ответа API; при отсутствии текста — «Не удалось выполнить запрос. Попробуйте ещё раз.». Отмена запроса уведомление не создаёт. Ошибка остаётся отклонённым Promise для вызывающего кода. Терминальные ошибки фоновых заданий в успешных HTTP-ответах нужно обрабатывать в соответствующем пользовательском сценарии.
- Уведомления всегда расположены сверху по центру и показываются по очереди, одинаковые сообщения в очереди не дублируются. Закрытие — кнопкой, Escape или автоматически через 6 секунд; клик вне уведомления его не закрывает. Снэкбары выезжают из-за верхнего края и уходят обратно за него за 300 мс с учётом уменьшения движения. Следующий снэкбар появляется после завершения анимации закрытия предыдущего. Пасхалка показывает информационный снэкбар с комплиментом через 3 минуты после открытия приложения, затем с новым случайным интервалом от 5 до 120 минут. Переходы между страницами не перезапускают таймер; закрытие приложения удаляет его.

Иконки: [Tabler Icons](https://github.com/tabler/tabler-icons), MIT. SVG и текст лицензии находятся в `public/icons/snackbar`. Runtime-пакет иконок не установлен. Для показа/скрытия пароля используются SVG `eye`/`eye-off` из того же официального набора; файлы и копия MIT-лицензии находятся в `public/icons/password`. Переключатели доступны с клавиатуры и блокируются вместе с полями во время запроса.

## Режим моков

В `.env.local` задайте `developerMode=mock`, чтобы все 54 операции работали без backend. Значения `dev`, `test`, любые другие значения и отсутствие переменной оставляют стандартные запросы к API. Проверка точная: `MOCK` не включает моки.

`src/mock/bodies.json` содержит исходные примеры backend-контракта; они служат основой ответов с теми же полями. `src/mock/responses.json` задаёт методы, маршруты и HTTP-статусы 54 операций backend. Ещё два маршрута из `src/mock/authResponses.json` подтверждают вход и сброс только внутри mock-адаптера; при других режимах сервис не отправляет их в сеть, поскольку реальный API таких методов пока не описывает. Endpoint согласия использует локальную редакцию документа и соответствующий SHA-256.

В режиме mock перед изменениями нет запроса или проверки CSRF. Если сервис CSRF вызывается явно, он также возвращает локальный ответ без сети. Моки поддерживают вход, регистрацию, подтверждение почты, выход, создание и изменение компаний, участников и приглашения, баланс и операции, платежи и сопоставления, импорты, подключения, прогнозы и сценарии. Созданные данные доступны в последующих запросах. Списки поддерживают пагинацию и фильтры сервисов. Версии проверяются; повтор изменения с тем же `Idempotency-Key` возвращает прежний результат без повторной записи. Неизвестные ресурсы возвращают ошибки API через общий снэкбар.

Демо-сессия и данные сохраняются в localStorage под ключом `saldo-mock-state-v1` и переживают перезагрузку. Пароли не сохраняются. При первом открытии пользователь не авторизован; войти можно с любыми значениями полей. После входа, регистрации и запроса сброса открывается экран четырёхзначного кода. В mock принимается любой четырёхзначный код; нули в ячейках — только плейсхолдеры. До подтверждения входа демо-сессия не активна. Подтверждение почты после регистрации сразу создаёт демо-сессию; после подтверждения регистрации или входа открывается дашборд. После подтверждения сброса открывается форма нового пароля. Письма не отправляются. Для сброса демо-данных удалите этот ключ и перезагрузите страницу.

Задержка ответа в браузере — 300 мс, отмена запроса поддерживается без изменения данных. Запуски импорта и прогноза возвращают `202`; следующий запрос получает готовый результат. Импорт имитирует обработку файла на демонстрационных записях, CSV не разбирается. Новый прогноз рассчитывается по демо-платежам, ML и внешние интеграции не вызываются. Поддерживаются изменения, объявленные доступными в `scenario_capabilities`; статистическая вероятность кассового разрыва не выдумывается. Дашборд использует те же сервисы; кабинет показывает данные пользователя и кнопку выхода.

`developerMode` явно передаётся в браузер через `next.config.ts` и фиксируется при сборке. После изменения значения перезапустите dev-сервер; для production пересоберите приложение. Секреты в этой переменной не храните.

## Авторизация

Открытые маршруты: `/login`, `/register`, `/verify-code`, `/forgot-password`, `/reset-password`. Код использует `purpose=login`, `purpose=reset` или регистрацию по умолчанию. В реальном режиме сброс принимает токен из ссылки `/reset-password?token=…`; согласуйте адрес ссылки с backend. Формы центрированы, имеют максимальную ширину 750 px и отступы от краёв экрана минимум 10 px. Регистрация объединяет имя и фамилию в `display_name`. Все проверки регистрации, восстановления и кода выполняются в TypeScript до запроса; ошибки показываются снэкбаром. Нативная HTML-валидация отключена во всех формах. На входе клиентской валидации нет: даже пустые поля передаются API. Окно подтверждения содержит четыре цифровые ячейки с placeholder `0`, вставкой кода, автопереходом и анимацией цифр. Текущий реальный API описывает токен длиной 16–512 символов: поэтому вне mock форма принимает полный токен из письма и отправляет его backend без локального подтверждения.

Видимые лейблы над полями показаны только во входе и регистрации. Размеры текста всех форм берутся из регистрации. Фон поля при фокусе плавно меняется на `gray1`; недоступные поля имеют opacity `0.4`. Переходы занимают `0.3s` и отключаются при `prefers-reduced-motion`.

`Spinner` экспортируется из `src/widgets`; кнопкам запросов передавайте `loading` в `AuthButton`. Пока запрос выполняется, спиннер заменяет содержимое кнопки, сохраняя её высоту и ширину; повторные нажатия блокируются. Повторная отправка кода также показывает спиннер.

Остальные страницы, кроме публичных документов, проверяют cookie-сессию через `/me` перед показом содержимого. Любая неудачная проверка входа, включая сетевую ошибку и `5xx`, ведёт на `/login`. Одновременные ошибки вызывают только один переход. Документы не проверяют `/me` и доступны всем. На страницах авторизации сессия проверяется без уведомления об ожидаемом отсутствии входа: гостю показывается форма, вошедший пользователь перенаправляется на `/`. После выхода сессия очищается, а попытка открыть защищённую страницу ведёт на `/login`; циклических редиректов нет.

Для автоматического входа после регистрации реальный backend должен устанавливать session cookie при подтверждении почты: клиент затем получает пользователя через `/me` и открывает дашборд. Сейчас контракт подтверждения возвращает только acknowledgement; при отсутствии сессии клиент переводит на вход. Подтверждение входа письмом требует отдельного backend challenge/confirm-контракта; текущий `/auth/login` сразу создаёт сессию. Полная цепочка подтверждения входа уже работает в mock.

Browser access/refresh-токены и endpoint обновления сессии отсутствуют в текущем контракте. Клиент не выдумывает refresh-запрос и не повторяет изменения при `401`: истёкшая сессия требует нового входа. После появления согласованного endpoint можно добавить обновление сессии перед перенаправлением.

Флажок «Запомнить меня» сохраняет только почту для следующего входа. Пароль, подтверждающий токен и session cookie в web storage не сохраняются; срок сессии контролирует сервер.

## Docker

Из каталога проекта:

```bash
cp .env.example .env.local
docker compose --env-file .env.local up --build -d
```

Приложение: `http://localhost:3000`. Compose публикует `3000:3000`.

Dockerfile использует многоэтапную сборку Node.js 24 Alpine и Next.js standalone. В runtime копируются только сервер, его зависимости, static и public; процесс работает от пользователя `node`. `.dockerignore` исключает локальные зависимости, сборки, Git и env-файлы из контекста.

`NEXT_PUBLIC_API_URL` и `developerMode` передаются как build args из `.env.local`. Для изменения API или включения моков (`developerMode=mock`) пересоберите образ той же командой. Runtime-подмена этих значений не меняет уже собранный браузерный код.

Полоса прокрутки оформлена глобально в `src/app/scrollbar.scss`: дорожка цвета фона, чёрный ползунок, скругления и толщина 8 px для обеих осей; Firefox использует доступное браузеру тонкое оформление.
