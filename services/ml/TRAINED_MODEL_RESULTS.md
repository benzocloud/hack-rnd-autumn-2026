25.10.2026. **Улучшение качества не получено; переключать продукт не рекомендуем.**
Обучаемый `linear_pool_90` выбрал веса `[4,0,0]` для прихода и расхода:

тот же угол сетки лучший. Это вывод о 225 заданных сочетаниях, не обо всех моделях.

## Модель и обучение

Модель смешивает три оценки отдельно для прихода/расхода: среднее за 90 дней,
среднее за 30 дней и среднее того же дня недели за 8 недель. Все веса
неотрицательные, сумма 1, шаг 1/4; 15 × 15 = 225 фиксированных сочетаний.
Это обучаемая статистическая смесь, **не MLP и не классификатор GBM30/QRF**.
Последние не заменяют дневные деньги/компоненты без отдельной адаптации.

Обучение: 507 неперекрывающихся окон, 125 компаний, исходы известны до
30.09.2025, последняя использованная целевая дата 28.09.2025. Цель — средняя
по компаниям MAE дневного остатка в единицах прошлого дневного оборота.
FP на train не выше mean_90 на тех же окнах; у выбранной точки 33 FP.
Точный Fraction-критерий и tie-break детерминированы. Seed 20261024 — для
существующих empirical bands; случайного оптимизатора у перебора нет.

Обучение не читает исходы после этой даты при выборе весов. После выбора
артефакт фиксируется. Последующие rolling-origin окна с cutoff >30.09.2025
используют этот **один** артефакт без переобучения и подбора по validation/late.
Запрос на cutoff раньше trained_through отвергается как FailedPrecondition.
Проверка модели не зависит от наличия сегодняшнего календаря.

## Coverage и границы оценки

Исходный календарь baseline: 01.01.2025–31.08.2026, шаг 30, горизонт 30,
история 90 дней; те же history_at/truth_window и temporal split. Из 3 150
кандидатных окон допустимы 1 232. Причины исключения: нет observed cutoff
EOD 1 097; пересечение temporal split 300; вне наблюдаемой истории 363;
короткая история 66; history reconciliation gap 72; future gap 17;
неполная будущая цель 1; дубли будущего 1; дубли истории 1.

507 окон — обучение/недоступность этой модели в прошлом, не тест. Остальные
725 оценены одинаково для mean_90, weekday_8w и кандидата:
205 development, 204 validation, 316 late. Из них отрицательный начальный
остаток имеют 4/8/10 окон, они учитываются отдельно от новых разрывов.
Будущие окна за концом данных не заполнялись нулями; пропуски не исправлялись.
Категории и доступность календаря не восстанавливались из будущих фактов.
Поздние данные и validation ранее исследовались, **независимого holdout нет**.
Числа нельзя смешивать с более плотным протоколом v2 на 11 165 окнах.

## Подключение и сценарии

Единственный RPC — прежний `ml.v1.ForecastService/Predict`. Старые профили
сохраняют контекст и ответы. Изменены только выбор поддерживаемой версии и
расчёт uncovered-компонент после **общей** неизменённой проверки/replacement.
Новый kind — `linear_pool_uncovered`, прежние kind не переименованы.
Категории, regularity, history evidence, scope/snapshot/calendar identity
и data_version сохраняются; Core владеет итоговым балансом и хранением.

Проверены новый платёж, перенос, частичная оплата с исполненным фактом в группе,
отмена, отсутствие календаря, duplicate replacement и int64 overflow.
Пять ответов старого финансового профиля совпали побайтно с pre-change hashes.
Новый профиль прошёл настоящий локальный mTLS с Core-идентичностью; чужая
идентичность отклонена. Это **не вызов настоящего Go Core**.

На C015 (303 операции/90 дней, приход в 70% дней) и C071 (74 операции,
приход в 26.7% дней) реальный ML RPC совпал с offline каждым днём.
Синтетические добавление/перенос/частичная оплата/отмена проверены отдельно
от качества модели; сценарии явно подписаны как придуманный календарь.
20 повторных mTLS-вызовов окончательной версии: p50 15.69 мс, p95 17.87 мс
на этой Windows-машине. У mean_90-угла переиспользуется математически та же
allocation без лишних category feature maps; identity модели не подменяется.
Это latency примеров, не нагрузочная гарантия для 0.5 CPU/192 MiB production.
Чистый offline расчёт: p50 0.48 мс, p95 0.79 мс; транспорт/bootstrap не включены.
Одноразовая PKI была только в памяти, локальный сервер остановлен.

Диапазоны остаются «чувствительность сценария, не вероятность»:
512 paired moving-block bootstrap, блок 7 дней, nominal q0.1/q0.9,
calibrated=false. Нового доказательства покрытия нет; probability oneof
всегда unavailable/not_calibrated. ТЗ по вероятности остаётся открытым.

### Точный blocker Core на проверенном main

- `services/core/internal/service/forecasting/model.go:11`: application
  ModelContext содержит только Name/Version/PreprocessingVersion; не фиксирует
  требуемые checksum configuration/seed/trajectory_count новой модели.
- `services/core/internal/client/ml/financial.go:42`: encodeFinancial принимает
  только mean_90_components_v1; там же configuration жёстко равен этой версии.
- В том же файле строки 157–160 требуют постоянные mean_90 потоки, а не
  проверку формулы конкретной новой версии. Не ослаблять общую money identity.
- `financial_evidence.go:50` принимает только mean_90_uncovered;
  новый kind требует отдельной семантической проверки владельцем Core.
- Ручной календарь Core пока UNAVAILABLE, KnownPayments отклоняются.
  Его рабочее подключение остаётся отдельной задачей владельца Core.

Нужны явный выбор/сохранение полного model context, поддержка нового профиля
в кодеке и consumer checks, финансовый E2E с ручным календарём. Это **не одна
переменная окружения**. Ничего из перечисленного в этом PR не меняется;
переход сейчас не рекомендуется, поскольку веса всё равно mean_90.
Возврат к прежнему профилю — Core продолжает выбирать существующий mean_90;
исторические задачи/результаты не пересчитываются. Merge/deploy — отдельно.

Output обязан быть новым; входы сверяются с двумя закреплёнными SHA.
Первый запуск и повторный после форматирования вернули одинаковые artifact,
все 225 train-loss, метрики, per-company и прогнозы. Независимым арифметическим
скриптом сверены 21 750 дневных точек frozen mean_90, MAE и RMSE.

Локальные bindings сгенерированы из текущего proto через grpc_tools 1.78.0,
как в существующем Dockerfile; в Git не включены, proto не изменён.
