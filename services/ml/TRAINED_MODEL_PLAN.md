## Решение и границы

QRF/GBM30/QMIN выдают скаляр риска/минимума, а согласованный Predict требует
дневные потоки, компоненты и точную reconciliation. Поэтому в этом PR один
компактный обучаемый кандидат `linear_pool_90`: выпуклая смесь mean_90,
mean_30 и weekday_8w с разными весами прихода/расхода. Веса действительно
обучаются на прошлых денежных траекториях; это не нейросеть и не вероятность.

Новый профиль `linear_pool_components_v1`, preprocessing
`calendar_replacement_v1`, точный configuration_id/checksum закреплённого JSON.
Существующие mean_90 профили сохраняют поведение. По умолчанию Core остаётся
на mean_90: его проверки отвергают другую model identity и непостоянные потоки.
Не обходим этот отказ; в отчёте — конкретные точки подключения для владельца.

Runtime — стандартная библиотека Python, целые копейки/Fraction. Категории,
regularity и provenance сохраняются. Исключение заменяемых фактов выполняется
**до** любых трёх оценок; известные remaining добавляются ровно один раз.
Новая остаточная компонента имеет отдельный kind; старые значения не переименовываем.
Горизонт 30, история 90, все существующие входные проверки остаются.
Диапазоны — прежняя явно неоткалиброванная чувствительность; вероятности unavailable.
Входа CSV/DB в inference нет. JSON с шестью весами не содержит исходных строк.

Разрешены только services/ml/. Не меняем proto/generated/docs общие/Core/API/
Auth/frontend/deployment/CI/scripts. Сервис в рабочем окружении не запускаем
и не перенастраиваем. Тестовый mTLS — только локально с одноразовой PKI.

## Фиксированный протокол до обучения

- Данные участников: SHA фиксируются до первого расчёта; CSV read-only.
- Календарь окон исходного baseline: 01.01.2025–31.08.2026, шаг 30,
  горизонт 30. Те же history_at/truth_window/temporal split/eligibility.
  Исходный результат baseline дополнительно сверяется при наличии frozen CSV.
- Train: только окна с полностью наблюдаемой целью до 30.09.2025 включительно.
  Минимум 100 окон и 20 компаний; иначе явная остановка, без подмены обучения.
- В каждой стороне 15 троек целых весов 0..4 с суммой 4: шаг 1/4, всего
  225 сочетаний. Перебор детерминированный, seed=20261024 фиксирует bands.
- Критерий train: минимальная средняя по компаниям MAE дневного остатка,
  нормированная прошлым средним дневным оборотом (не будущим остатком).
  Ограничение: FP новых разрывов на train не выше mean_90 на тех же окнах.
  При равенстве предпочитаем больший вес mean_90, затем лексикографический порядок.
  Угол 100% mean_90 разрешён: не заставляем обучение выбирать худшую смесь.
- После выбора веса замораживаются. Ни validation, ни late, ни тестовый
  development не участвуют в выборе. Рабочий JSON trained_through=30.09.2025;
  inference на более раннем cutoff явно отвергается.
- Оценка rolling-origin на последующих доступных cutoff >=01.10.2025:
  оставшийся development, validation Jan–Mar2026, late Apr–Sep2026.
  Пересекающие границы горизонты исключаются как у baseline.
  Это повторно изучавшийся датасет, не независимый holdout.
- Контроли: production financial mean_90 с UNAVAILABLE calendar и простой
  weekday_8w. Исторического платёжного календаря нет — не выдаём его за пустой
  подтверждённый календарь. Ручные платежи проверяем отдельно на синтетике.
- Метрики: MAE/RMSE дневного/конечного остатка, WAPE/MAE потоков, TP/FN/FP/TN,
  precision/recall/F1/FPR, уникальные эпизоды, ошибка даты/глубины, по компаниям,
  continuing отдельно, latency p50/p95. Нулевые знаменатели — null.
- Рекомендовать замену разрешено только при меньшей MAE остатка, FP не выше
  mean_90 и найденных эпизодах не меньше в development и validation.
  Отказ gate не запрещает отдельный явно экспериментальный профиль в PR;
  default/deploy не меняем и превосходство не обещаем.

## Этапы

1. **В работе: воспроизводимое обучение и фиксированный артефакт.**
   services/ml/cashflow_rpc/trained_pool.py, services/ml/train_model.py,
   services/ml/cashflow_rpc/model_assets/*.json и *.sha256. Этот каталог уже
   копируется существующей Docker-сборкой; deployment менять не требуется.
   Сохранить manifest до fit, все 225 train-loss, веса, SHA, исключения;
   проверить exact arithmetic и отсутствие будущих данных. Результат —
   воспроизводимый малый артефакт без финансовых строк.
2. **Не начат: подключение отдельной версии к Predict и финансовые проверки.**
   Минимальные изменения cashflow_rpc/financial.py и выбора модели server.py;
   общая reconciliation для старой/новой версии. Проверки нового/перенесённого/
   частично оплаченного/отменённого платежа, UNAVAILABLE calendar, переполнения,
   старых контекстов/неверных версий и checksum. Existing profiles unchanged.
3. **Не начат: оценка, оба review, публикация.**
   Rolling backtest, артефакт/латентность, полный ML и RPC/mTLS без skips,
   Ruff pinned/format, семантический review caveman + ponytail. Исправить
   подтверждённые дефекты, записать фактические границы. Перед push/PR снова
   fetch/merge main/ancestor и затронутые проверки. Один draft PR `ML: feat: ...`,
   русский body, английский commit; не merge/deploy.

Главные риски: мало новых разрывов; дрейф после train; неизвестная независимая
точность; Core не принимает новую identity; будущий PR44 добавит неподдерживаемые
поля. Не ослабляем потребителей и не переносим будущие факты в прошлые признаки.
