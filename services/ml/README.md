# Локальные cash-flow baseline

Два фиксированных детерминированных прогноза на 30 календарных дней:

- `mean_90`: средние дневные поступления и расходы за последние 90 дней.
- `weekday_8w`: средние поступления и расходы соответствующего дня недели
  за последние 8 недель. Для любого будущего дня используются только прошлые данные.

Из прогнозных потоков рассчитывается остаток от наблюдаемого EOD даты среза.
В этих двух baseline обучения, вероятности риска, категоризации и платёжного
календаря нет; дополнительные локальные эксперименты описаны ниже.
Для mean_90 добавлен отдельный gRPC endpoint по снимку Core:
[контракт, генерация, запуск и ограничения](GRPC_CONTRACT.md).
Сам Core ещё не подключён; CLI evaluation остаётся исследовательским запуском.

## Данные

По умолчанию ожидаются `data/cashflow/raw/companies.csv` и `all_operations.csv`.
Архив участников распаковать самостоятельно; общий файл и выписки по компаниям
содержат одну историю и не объединяются. Данные и результаты исключены из Git.

Основной код использует стандартную библиотеку Python. Для графиков нужен
Matplotlib; без него есть режим `--no-plots`. Проверено окружение Python 3.12.

## Проверка по времени и качество

Настройки зафиксированы в `baseline_config.json`. Кандидаты дат расчёта идут
с 2025-01-01 по 2026-08-31 с шагом 30 дней. Горизонт 30 дней; будущие окна
одной компании не перекрываются. Это фиксированный календарь, не выбор дат
с минимальной ошибкой. Оба метода используют одну и ту же подвыборку.

- Development: весь будущий горизонт раньше 2026-01-01.
- Validation: весь горизонт с 2026-01-01 до 2026-04-01.
- Evaluation: весь горизонт с 2026-04-01 по 2026-09-30 включительно.
- Горизонт через границу частей исключается.

Поздняя история уже исследована при EDA. Evaluation не является нетронутым
финальным test. Параметры методов фиксированы; автоматического подбора нет.

Вход восстанавливается из исходных операций только по сведениям до cutoff.
Ретроспективные поля качества дневного экспорта не используются как признаки.
Начальный остаток должен быть наблюдаемым на cutoff; короткая история,
выявленный пропуск с расхождением больше копейки или кандидат в дубли
исключают соответствующий пример. Расхождение в одну копейку сохраняется
как предупреждение, а не исправляется фиктивной операцией.

Качество будущей цели проверяется отдельно по доступному полному набору,
не передаваемому методам прогноза. Это ретроспективный отбор надёжных целей,
который может менять состав выборки и не доказывает полноту остальных данных.
Будущий горизонт за концом истории не дополняется нулями.

Дни без строк внутри истории считаются нулевым движением как явное допущение;
остаток переносится, пока не обнаружено противоречие. Пропуски с нулевым чистым
эффектом могут остаться невыявленными. Поэтому отчёт отдельно считает
использования перенесённых значений. На праздничных/рабочих переносах календаря
РФ недельный baseline может ошибаться: production calendar не подключён.

## Результаты

`services/ml/artifacts/baseline/`:

- `report.html`: автономный отчёт с встроенными графиками; открывается браузером.
- `report.md`: текстовая версия.
- `metrics.json`: метрики по временной части, компании и отрасли.
- `predictions.csv`: дневной факт/прогноз и происхождение фактического остатка.
- `eligibility.csv`: каждый кандидат с причиной включения/исключения.
- `manifest.json`: настройки, SHA-256 источников, версии Python и библиотек.
- `example_*.png`: диагностические графики.

WAPE относится отдельно к входящему/исходящему потоку; нулевой знаменатель
даёт `null`, а не фиктивную нулевую ошибку. Дополнительно считаются медианные
WAPE компаний, MAE дневного/конечного остатка, медиана MAE компаний.
Дневная WAPE и WAPE сумм потоков за весь горизонт считаются отдельно:
правильная месячная сумма не означает правильные даты поступлений и расходов.
Ошибки даны в денежных единицах источника; валюта в CSV явно не определена.

Классификация означает хотя бы один отрицательный EOD в горизонте. Новые
отрицательные остатки и продолжение уже отрицательных оцениваются отдельно:
TP/FP/FN/TN, precision/recall, дата первого минуса и величина дефицита.
Это не проверка внутридневной платёжеспособности, овердрафта или всех счетов.
`gap_probability` остаётся `null`: детерминированный baseline не даёт вероятности.

## Эксперимент: категории и регулярные платежи

`run_recurring.py` добавляет третий метод `calendar_hybrid`, сохраняя оба
baseline и все их срезы/прогнозы неизменными. Старые API и конфигурация не меняются.

Категории определяются прозрачными правилами назначения и направления операции.
Есть `unknown`; пустой текст не заполняется придуманной категорией. Зарплатный
аванс и окончательный расчёт отделены друг от друга, комиссий и других операций
того же банка. Налог не определяется по общей приписке «Без налога (НДС)».
`rule_confidence` — эвристический приоритет, а не измеренная accuracy или
вероятность; категорий ground truth нет. Операции не удаляются.

Ежемесячная регулярность ищется по направлению, категории и контрагенту
в последних 180 днях, известных на cutoff. Минимум 3 подтверждения для
регулярных расходов, 4 для остальных групп; покрытие периодов не ниже 75%,
допуск даты 4 дня. Сумма — медиана последних трёх совпавших событий.
Номинальный день/конец месяца и перенос выходного вперёд/назад выбираются
по прошлым датам. Праздники РФ не подключены; предсказанное событие — гипотеза.
Одноразовые займы/финансирование, собственные переводы и эквайринг не объявляются
ежемесячными обязательствами. Для обычных клиентских оплат/прочих расходов
дополнительно требуется устойчивость суммы.

Совпавшие исторические события вычитаются из дневных потоков, остаток
прогнозируется прежним `weekday_8w`, а будущие события добавляются один раз.
Ранний уже состоявшийся платёж не прогнозируется повторно в том же периоде.
Неопределённые операции остаются в остаточном потоке. Расписание сезонного
кредита не восстанавливается из его будущего погашения.

Для воспроизведения сначала нужен неизменяемый результат двух baseline:

```powershell
& '.\.venv\Scripts\python.exe' services/ml/run_baseline.py --output-dir services/ml/artifacts/baseline_43d7a28
& '.\.venv\Scripts\python.exe' services/ml/run_recurring.py
```

Если исходные результаты уже сохранены в этой папке, первую команду повторять
не нужно. Альтернативный путь — `--reference-dir <папка baseline>`; доступны
`--data-dir`, `--output-dir`, `--no-plots`. Эксперимент проверяет SHA источников,
совпадение конфигурации, побайтовое равенство исходного CSV прогнозов и равенство
метрик. При отличиях останавливается; окна не исключаются новым методом.

Результаты только в игнорируемом `services/ml/artifacts/recurring_v2/`.
Архив предыдущих правил `recurring_v1/` сохраняется отдельно и не перезаписывается:

- `comparison.html` / `comparison.md`: сравнение и графики всех пяти случаев.
- `gap_cases.md` / `gap_cases.json`: крупные расходы и доступные прошлые аналоги.
- `categorized_operations.csv`, `category_summary.json`: категории всех операций,
  использованное правило и покрытие, без заявления измеренной точности.
- `recurring_patterns.csv`, `expected_events.csv`: гипотезы и ожидаемые события
  с cutoff и датами исторических подтверждений.
- `predictions.csv`, `metrics.json`, `eligibility.csv`, `manifest.json`: все три
  метода, причины отбора, источники и проверка идентичности baseline.

Пять случаев используются для объяснения ошибок, а не независимого test.
Сравнивать нужно также ложные тревоги и ошибки на всех окнах. Вероятности риска,
договоры и подтверждённые обязательства этим экспериментом не добавляются.

## Проверка категорий и прогноз поступлений

Ручное чтение ассистентом 141 операции из 30 компаний выявило 44 расхождения
с широкими категориями. После исправлений на этой целевой выборке расхождений
нет; это не независимая человеческая разметка и не accuracy всего датасета.
Отделены маркетплейс/агентская выручка, страховые выплаты, гранты, капитал,
удержания по договорам и личные выводы. Для «собственных средств» без источника
есть `self_funding_unknown`; пустые назначения остаются `unknown`.

```powershell
& '.\.venv\Scripts\python.exe' services/ml/run_inflow.py
# Если сохранена локальная ручная разметка:
& '.\.venv\Scripts\python.exe' services/ml/research/category_audit.py --review services/ml/artifacts/inflow_v2/manual_review.json
```

Нужен тот же frozen reference, что для `run_recurring.py`. `run_inflow.py`
использует только стандартную библиотеку; доступны `--data-dir`,
`--reference-dir`, `--output-dir`. Исходные источники, конфигурация, прогнозы
baseline и 1 232 среза проверяются перед сравнением. Расходы новых вариантов
остаются `mean_90`, параметры выбираются по validation; все попытки показаны.

`seasonal_receipts` смешивает 50/50 операционные поступления среднего уровня
90 дней и тот же день недели год назад (364 дня, +/- две недели), с поправкой
роста, ограниченной 0,5–2. Неоперационные поступления, свои переводы и unknown
сохраняют полный компонент среднего за 90 дней. При отсутствии/плохом качестве
старой истории применяется fallback `mean_90`. Операции не удаляются и
не обнуляются по категории. Обе стороны собственного перевода не консолидируются.

`inflow_v2/comparison.md`, `metrics.json`, `selection.json`, `diagnostics.json`,
`explanations.json`, `positive_cases.csv`, `predictions.csv` и `manifest.json`
лежат только внутри `services/ml/artifacts/`. `selection.json` содержит также
неудачные варианты, `explanations.json` — наличие годовых данных и решения
выбора на прошлых окнах. Локальная разметка/детальные операции не публикуются.
Краткие воспроизводимые результаты: `.agent/research/ml-inflow-results.md`.

В validation выбирается сезонный вариант; в поздней диагностике он улучшает
поступления против `mean_90`, но ухудшает остаток и число ложных тревог.
Поэтому это экспериментальный метод, `run_baseline.py` по умолчанию сохранён.
Поздние данные исследовались между гипотезами: не объявлять их независимым holdout.

Для отдельного исследования собственных переводов:
`python services/ml/research/own_transfers.py`. Отчёт и ограничения мультисчётности:
`.agent/research/own-account-transfers.md`. Это исследование не включает
реализацию консолидации или изменение API.

## Ежедневный остаток, события и сценарии

`run_balance.py` сохраняет исходные baseline и сравнивает их на тех же 1 232
окнах с каналами поступлений (`channel_expected`, `channel_events`), компактной
логистической моделью наличия поступления, строгим календарём расходов и
совместными вариантами. Отдельно проверяются только приход, только расходы
и оба потока. Все денежные вычисления — целые минимальные единицы/Fraction;
логистические коэффициенты — float, score переводится в фиксированную точность
до умножения на деньги. Новые библиотеки для обучения не нужны.

```powershell
& '.\.venv\Scripts\python.exe' -B services/ml/run_balance.py
& '.\.venv\Scripts\python.exe' -B services/ml/research/balance_audit.py
# Независимый повтор; папка результата должна быть новой:
& '.\.venv\Scripts\python.exe' -B services/ml/run_balance.py --output-dir services/ml/artifacts/balance_v1_replay
```

Нужен frozen reference `baseline_43d7a28`. Для старых контролей читаются локальные
`inflow_v2/predictions.csv` и `recurring_v2/predictions.csv`, если они есть;
факт/ключи/арифметика контролей проверяются. Их отсутствие не удаляет новые окна.
Доступны `--data-dir`, `--reference-dir`, `--output-dir`. Существующий output не
перезаписывается; исходники и reference не должны пересекаться с ним.

Окончательный результат — `services/ml/artifacts/balance_v1_verified/`:

- `comparison.md`, `metrics.json`: общий результат, каждая компания/отрасль,
  типы поступлений, ошибки остатков/потоков, TP/FN/FP, даты/глубина/время предупреждения.
- `selection_before_evaluation.json`: выбор по validation до поздних новых прогнозов;
  критерии и все отказы сохранены. Ни один кандидат не прошёл, выбран mean_90.
- `error_decomposition.csv`, `diagnostics.json`: ошибки суммы и времени каждого
  потока, концентрация/разовые события и причины исключения. Это диагностика,
  не будущие признаки и не доказательство причинности.
- `predictions.csv`, `eligibility.csv`, `manifest.json`: все окна, точные суммы,
  источники и хеши кода. Если код/основные CSV изменились в ходе запуска, он прервётся.
- `independent_audit.json`: отдельная проверка всех 443 520 дневных строк,
  неизменности старых baseline и наличия/отсутствия поступлений; ненулевое
  ожидание не объявляется точным предсказанием даты.
- `explanations.json`: прошлые подтверждения расходов, оплаченные периоды,
  прогнозные события, неопределённые каналы прихода и пример объяснения риска.
- `user_examples.md`, `reproducibility.json`: развёрнутые объяснения для пользователя
  и подтверждение побайтового совпадения двух полных запусков.
- `examples/`: операции, 90 дней прошлой истории и дневные прогнозы/графики
  C126/C032 на одинаковом срезе 2026-08-24.
- `human_audit/`: 260 новых примеров для двух людей, инструкция и отдельный ключ
  правил координатору. Человеческая разметка ещё не выполнена, accuracy нет.

Собственные переводы, займы и финансирование сохраняют полное влияние в
ожидаемом прогнозе. Нет консолидации счетов. Осторожный сценарий — отдельная
чувствительность к меньшим/поздним приходам и высокому прошлому уровню расходов,
не вероятность/доверительный интервал. Он дал слишком много ложных тревог и
не предлагается для автоматических уведомлений. Праздники РФ не подключены,
известных будущих графиков обязательств нет. Поздняя часть уже исследована:
это не независимый holdout. Default и API не менялись.

Человеческая разметка: [инструкция](../../.agent/research/ml-category-annotation-guide.md).

## Разбор ложных тревог календаря расходов

```powershell
& '.\.venv\Scripts\python.exe' -B services/ml/run_expense_warnings.py
& '.\.venv\Scripts\python.exe' -B services/ml/run_expense_warnings.py --output-dir services/ml/artifacts/expense_warnings_v1_replay
```

Нужны исходные CSV, frozen baseline и `balance_v1_verified/predictions.csv`.
Доступны `--data-dir`, `--reference-dir`, `--previous-dir`, `--output-dir`;
папка вывода должна быть новой и не пересекаться с источниками/контролями.
Новый эксперимент воспроизводит оба baseline и прежний expense_only, разбирает
каждую общую/новую/исчезнувшую FP и проверяет одну гипотезу `expense_past_gate`:
календарь применяется только после >=5% выигрыша ошибки остатка без роста прошлых
новых FP/FN на двух полностью прошлых 30-дневных окнах. Непригодная дополнительная
история означает fallback, наружные окна не удаляются.

Результаты — в `services/ml/artifacts/expense_warnings_v1/`: `comparison.md`,
`warning_cases.json/csv`, `warning_summary.json`, `gate_evidence.json`,
`metrics.json`, `predictions.csv`, `eligibility.csv`, `audit.json`, `manifest.json`.
Детальные платежи/назначения остаются локальными. Сопоставление прогнозного
события с будущей фактической группой — только диагностическая эвристика,
не признак для gate и не подтверждение обязательства/неоплаты.

На validation и поздней части gate полностью совпал с mean_90 из-за fallback;
улучшения не доказано, default сохранён. Поздняя часть ранее изучалась.
68 ML-тестов и два полных совпавших запуска проверены. Итог:
[причины ложных тревог](../../.agent/research/ml-expense-warning-results.md).


## ML gRPC

Canonical контракт — `proto/ml/v1/forecast.proto`, приватный
`ml.v1.ForecastService/Predict`. Вход — согласованный Core snapshot за 90 дней,
дневные суммы в копейках, observed EOD на cutoff и явные версии. Ответ —
1..30 дневных прогнозов mean_90. Непустой known_payments отклоняется до
согласования устранения двойного учёта. Вероятность разрыва не рассчитывается.
