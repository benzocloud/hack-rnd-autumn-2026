# Локальные cash-flow baseline

Два фиксированных детерминированных прогноза на 30 календарных дней:

- `mean_90`: средние дневные поступления и расходы за последние 90 дней.
- `weekday_8w`: средние поступления и расходы соответствующего дня недели
  за последние 8 недель. Для любого будущего дня используются только прошлые данные.

Из прогнозных потоков рассчитывается остаток от наблюдаемого EOD даты среза.
Обучения, вероятности риска, категоризации, платёжного календаря и gRPC здесь нет.
Это локальный эксперимент, не реализованный сервис или принятый API-контракт.

## Данные

По умолчанию ожидаются `data/cashflow/raw/companies.csv` и `all_operations.csv`.
Архив участников распаковать самостоятельно; общий файл и выписки по компаниям
содержат одну историю и не объединяются. Данные и результаты исключены из Git.

Основной код использует стандартную библиотеку Python. Для графиков нужен
Matplotlib; без него есть режим `--no-plots`. Проверено окружение Python 3.12.

Из корня репозитория в PowerShell:

```powershell
python -m venv .venv
& '.\.venv\Scripts\python.exe' -m pip install -r .agent/infra/requirements-dev.txt -r services/ml/requirements-dev.txt
& '.\.venv\Scripts\python.exe' services/ml/run_baseline.py
```

Для другого расположения данных:

```powershell
& '.\.venv\Scripts\python.exe' services/ml/run_baseline.py --data-dir 'D:\path with spaces\dataset' --output-dir 'services/ml/artifacts/baseline'
```

Быстрая проверка одной компании без дополнительных библиотек:

```powershell
python services/ml/run_baseline.py --company C001 --no-plots --output-dir services/ml/artifacts/smoke
```

## Проверка по времени и качество

Настройки зафиксированы в `baseline_config.json`. Кандидаты дат расчёта идут
с 2025-01-01 по 2026-08-31 с шагом 30 дней. Горизонт 30 дней; будущие окна
одной компании не перекрываются. Это фиксированный календарь, не выбор дат
с минимальной ошибкой. Оба метода используют одну и ту же подвыборку.

- Development: весь будущий горизонт раньше 2026-01-01.
- Validation: весь горизонт с 2026-01-01 до 2026-04-01.
- Evaluation: весь горизонт с 2026-04-01 по 2026-09-30 включительно.
- Горизонт через границу частей исключается.

Поздняя история уже исследована при EDA. Evaluation не является нетронутым
финальным test. Параметры методов фиксированы; автоматического подбора нет.

Вход восстанавливается из исходных операций только по сведениям до cutoff.
Ретроспективные поля качества дневного экспорта не используются как признаки.
Начальный остаток должен быть наблюдаемым на cutoff; короткая история,
выявленный пропуск с расхождением больше копейки или кандидат в дубли
исключают соответствующий пример. Расхождение в одну копейку сохраняется
как предупреждение, а не исправляется фиктивной операцией.

Качество будущей цели проверяется отдельно по доступному полному набору,
не передаваемому методам прогноза. Это ретроспективный отбор надёжных целей,
который может менять состав выборки и не доказывает полноту остальных данных.
Будущий горизонт за концом истории не дополняется нулями.

Дни без строк внутри истории считаются нулевым движением как явное допущение;
остаток переносится, пока не обнаружено противоречие. Пропуски с нулевым чистым
эффектом могут остаться невыявленными. Поэтому отчёт отдельно считает
использования перенесённых значений. На праздничных/рабочих переносах календаря
РФ недельный baseline может ошибаться: production calendar не подключён.

## Результаты

`services/ml/artifacts/baseline/`:

- `report.html`: автономный отчёт с встроенными графиками; открывается браузером.
- `report.md`: текстовая версия.
- `metrics.json`: метрики по временной части, компании и отрасли.
- `predictions.csv`: дневной факт/прогноз и происхождение фактического остатка.
- `eligibility.csv`: каждый кандидат с причиной включения/исключения.
- `manifest.json`: настройки, SHA-256 источников, версии Python и библиотек.
- `example_*.png`: диагностические графики.

WAPE относится отдельно к входящему/исходящему потоку; нулевой знаменатель
даёт `null`, а не фиктивную нулевую ошибку. Дополнительно считаются медианные
WAPE компаний, MAE дневного/конечного остатка, медиана MAE компаний.
Дневная WAPE и WAPE сумм потоков за весь горизонт считаются отдельно:
правильная месячная сумма не означает правильные даты поступлений и расходов.
Ошибки даны в денежных единицах источника; валюта в CSV явно не определена.

Классификация означает хотя бы один отрицательный EOD в горизонте. Новые
отрицательные остатки и продолжение уже отрицательных оцениваются отдельно:
TP/FP/FN/TN, precision/recall, дата первого минуса и величина дефицита.
Это не проверка внутридневной платёжеспособности, овердрафта или всех счетов.
`gap_probability` остаётся `null`: детерминированный baseline не даёт вероятности.

## Проверки кода

```powershell
& '.\.venv\Scripts\python.exe' -B -m unittest discover -s services/ml/tests -p 'test_*.py' -v
& '.\.venv\Scripts\python.exe' -m ruff check services/ml
& '.\.venv\Scripts\python.exe' -m ruff format --check services/ml
git diff --check
```

Тесты покрывают денежную точность, календарь, независимость прогноза от будущих
операций, диагностику пропусков на дату расчёта, границы частей, дубли,
одинаковые окна методов и метрики новых/продолжающихся отрицательных остатков.
Существующие Linux-тесты инфраструктуры не заменяются этим набором.
