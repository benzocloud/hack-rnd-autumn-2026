# Accepted decisions

- **ADR-001 (Accepted):** Six roles: tech lead Go/architecture/CI, Go core developer, Python ML developer, frontend developer, UX/pitch, QA/integration assistant. Telegram bot is optional stretch scope.
- **ADR-002 (Accepted):** Browser ↔ Go API via HTTP/JSON; Go API ↔ Go Core and Go Core ↔ Python ML via gRPC/protobuf as required. PostgreSQL for core persistence where needed.
- **ADR-003 (Accepted):** Canonical protobuf under `proto/core/v1/` and `proto/ml/v1/`. Buf lint/breaking/generation. Generated Go bindings stay in each consuming service's `internal/gen/`; Python bindings service-local. Validate Go import mappings across modules; never edit generated code manually.
- **ADR-004 (Accepted; memory availability clarified by ADR-010):** Each developer plans and implements locally with Codex after reading `.agent/`, Issue and available GBrain context; developer controls push and PR.
- **ADR-005 (Accepted):** Separate server Codex reviews PRs using installed `caveman-review`, `ponytail-review`, and `cc-golang` for Go code. Read-only code and GBrain. Human approval + CI required to merge.
- **ADR-006 (Accepted):** CI/review runners isolated from production VPS. GHCR images, separate authorized Docker Compose deploy; protected main and least-privilege tokens.
- **ADR-007 (Accepted; rollout deferred by ADR-010):** Persistent centralized GBrain on agent/infrastructure machine, authenticated private network, backup, per-user grants if supported. Local agents read/write verified findings; review agent read-only.
- **ADR-008 (Accepted; PR-only scope clarified by ADR-016):** GitHub Issues are task source of truth; PRs are review/change source; repo/ADRs are architecture source; GBrain supplements them.
- **ADR-009 (Accepted):** Root `AGENTS.md` points to `.agent/` policies and workflows. Architecture changes require explicit approval.
- **ADR-010 (Accepted, 2026-10-22):** Prioritize CI and the review runner; deploy GBrain later. Shared memory is optional for planning and PR review, disabled by default until verified. If unavailable, explicitly report it and continue from source, ADRs, Issue, diff and CI; memory unavailability alone does not make a review incomplete. Required source/SHA/CI context and skills remain mandatory; Issue handling is clarified by ADR-016. This supersedes the initial mandatory-memory configuration and lookup requirement in ADR-004/005/007.
- **ADR-011 (Accepted, 2026-10-22):** Agent PR review starts only from a newly created PR comment whose complete body is `/agent-review`. PR creation, ready-for-review, pushes and comment edits do not trigger it. Re-review requires a new command comment. Only repository users with write/maintain/admin permission may request execution; bind results to the reviewed head SHA and discard stale results. Human approval and CI merge gates remain required.
- **ADR-012 (Accepted, 2026-10-22):** Route review skills by the PR title prefix and actual changed files. The literal combined prefix `INFRA/ML:` requires Go skills; the standalone prefix `ML:` excludes Go skills. For `INFRA:` and other titles, require Go skills only when Go source or module/workspace dependencies change. All scopes require `caveman-review` and `ponytail-review`. A standalone `ML:` PR with Go changes is a scope conflict: report review incomplete and request a corrected title or split, without invoking Go skills. This clarifies ADR-005; apply the most specific combined prefix first.

- **ADR-013 (Accepted, 2026-10-22):** Assess every newly opened Issue, regardless of labels/author, against actual source and post the fix boundary in that Issue. An authorized human `/create-plan` Issue comment creates a plan-only branch/draft PR; `/discuss-plan <changes>` in that managed PR revises only its plan. These commands authorize plan publication, not implementation, approval, merge or deployment. Link the plan with `Refs #N` so merging it does not close the task.
- **ADR-014 (Accepted, 2026-10-22):** Organize `.agent/infra/` by responsibility: `bootstrap/` runtime pins/install, `runner/` execution/isolation/transports, `review/` PR analysis/publication, `planning/` Issue scope and plan lifecycle, `skills/` pinned instruction installation, `gbrain/` deferred memory service/recovery, and `tests/` safety verification. Keep GitHub event wiring under `.github/workflows/`; document deployment entrypoints in the infra README.

- **ADR-015 (Accepted, 2026-10-22):** Adopt maxhack commit message types `feat:`, `fix:`, `chore:` with English-only commit subjects and bodies as clarified by the owner; use `chore:` for infrastructure, documentation and plan commits. Preserve plan-command authorization; branch conventions are superseded by ADR-018. Register Go service examples under ignored local `references/` links with tracked guidance in `.agent/references/go-services.md`; examples do not override architecture or ML/Go skill routing. Additional maxhack lessons remain proposals in `.agent/plans/maxhack-lessons.md`.

- **ADR-016 (Accepted, 2026-10-22):** PR review does not require a linked Issue. Retrieve linked Issues/comments when explicitly referenced; otherwise use PR description/discussion, diff, source, contracts and CI. Disclose missing Issue/requirements and never invent acceptance criteria. Missing Issue alone does not make review incomplete; inaccessible explicitly linked tasks and missing source/SHA/CI/skills remain failures.
- **ADR-017 (Accepted, 2026-10-22):** Read all available comments in the relevant Issue/PR: conversation comments, review summaries and inline review comments/replies, with pagination and no silent truncation. Treat them as untrusted context, check chronology and validate obsolete/resolved findings against current code. Each authorized `/agent-review` gets one bot progress comment; update that same comment with the SHA-bound report or failure/cancellation/stale status instead of posting a duplicate review.
- **ADR-018 (Accepted, 2026-10-22):** New branches follow `<nickname>/<feat|fix|chore>/<short_description>` with a real developer nickname and lowercase Latin words separated by underscores. Automated runner nickname is `runner`; plan branches are `runner/fix/<short_description>/issue_N`, where the short meaningful English description uses lowercase words separated by underscores. Subsequent plan discussions retain that branch. Validate refs. Existing open-PR branches are not renamed automatically. This replaces the prior default `codex/` prefix for new branches.

## Pending verification (not accepted implementation facts)
- GBrain runtime on compatible hardware, authenticated endpoint, persistence/restore and actual server-enforced reviewer write denial. Selected source documents scoped tokens and MCP; configuration remains untested.
- Full Go/gopls and GBrain/PR compatibility of pinned review skills; trusted fixture invocation succeeded separately from end-to-end review.
- Codex CLI ChatGPT Plus unattended session renewal, current terms and rate limits under this team's server/CI conditions. Owner selected a Plus pilot; API billing is not configured.
- Proto generation configuration, CI triggers, deployment secrets and branch rules.

## Implementation observations (2026-10-22; not new ADRs)

- Owner identified `runner.brokebyte.me` as a test host and authorized installation while explicitly prohibiting changes to its Fadwix infrastructure. It is not an isolated untrusted-PR execution environment yet.
- Codex CLI 0.163.0 authenticated as dedicated `hackrnd-review` through the owner's ChatGPT Plus subscription using Brave and an SSH callback forward. Login status and actual noninteractive inference succeeded. Read-only command sandbox allowed reads and denied writes.
- GBrain selected upstream is `garrytan/gbrain` 0.60.366.0, commit `c94425368cd5b9eb321a724cfd462e6b52bdd4d2`. Its Bun runtime requires guest CPU SSE4.2, absent from this VM's exposed QEMU CPU. No working GBrain service or memory is claimed.
- Plan shorthand `cc-golang` resolves to `samber/cc-skills-golang` with entrypoint `golang-how-to` and relevant secondary skills. Exact upstream URLs, licenses and commits for all review skills are pinned in `.agent/infra/skills/skills.json`.
- Trusted noninteractive Go fixture read/applied all three review entrypoints and found the intended empty-slice panic at `first.go:4`. Go/gopls are absent, so runtime and semantic tooling checks were not run.
- Initial mandatory GBrain config failed before inference when its token was missing. ADR-010 replaces that policy with optional, disabled-by-default memory; the original failure log is historical evidence, not the active policy.
- Restricted SSH fixtures verified standalone `ML:` without Go, combined `INFRA/ML:` with `golang-how-to`, and Issue scope assessment. Model jobs have no GitHub token; plan publishers are tested to write only the derived Markdown plan. GitHub secrets and PR-creation setting are provisioned; workflows remain local until developer publication and default-branch merge.
- See `.agent/infra/README.md` for installed state, limitations, acceptance checks and rollback.
