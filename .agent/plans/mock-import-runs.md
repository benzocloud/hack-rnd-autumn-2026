# Мок-прогоны импорта 1С и ФНС

Дата: 2026-10-23. План согласован разработчиком 2026-10-24 ответом «Да, реализуй этот план».
Статус реализации: на ревью разработчика; результат ещё не принят.
Основание: прямое поручение владельца реализовать генерацию документов,
имитацию импорта из 1С/ФНС и учёт полученных обязательств в расчёте.

## Цель и текущее состояние

Получить локальный воспроизводимый стенд, который одной командой генерирует
синтетические внешние документы, импортирует их через адаптеры, сохраняет
нормализованные данные и показывает изменение дневного денежного плана.

В репозитории нет реализованных Core/API/ML и финансового хранилища. Есть:

- `docs/data-contracts/normalized-source-batch.schema.json` — проект нашего
  нормализованного пакета;
- `docs/api/openapi.yaml` — проект браузерного контракта;
- `.agent/references/external-data-contracts.md` и `external-data-examples/` —
  найденные внешние форматы и ограничения;
- инфраструктурные Python-проверки и закреплённый Ruff 0.17.1.

`auth-service/` и `golang-arch/` — отдельные несвязанные локальные каталоги;
в рамках задачи не изменяются. Существующие незакоммиченные документы сохраняются.
Issue не назначен. GBrain недоступен/отключён; его сведения не использовались.

## Решения и границы

- Один локальный Python-стенд со стандартной библиотекой; без развёртывания,
  нового PostgreSQL, брокера или копирования финансовой модели в новый сервис.
- CLI выполняет полный прогон; простой HTTP-режим на `127.0.0.1` позволяет
  будущему импортёру читать сгенерированные файлы. HTTP-маршруты принадлежат
  нашему моку, не объявляются API поставщиков.
- Документы 1С используют подтверждённые namespace/поля ED 1.25: этапы оплаты
  и заявки на расход. Поддерживается явно описанное демо-подмножество;
  совместимость с любой конфигурацией и полным обменным сообщением не обещается.
- ФНС: имитация раздела предстоящих начислений справки ЕНС 1160082 по прочитанному
  описанию 5.03. Оригинальная XSD этой справки не получена: профиль помечается
  ограниченным. Уведомление 1110355 — отдельный пример налогового документа;
  отсутствие срока не превращается автоматически в платёж 28-го числа.
- Общий манифест отделяет транспорт/демо-данные от внешнего XML, содержит
  происхождение, тип профиля и явные допущения: RUB, неоплаченный остаток,
  даты доступности и связанные документы. Выдуманные значения — только демо.
- Адаптеры нормализуют исходные поля; деньги — целые минимальные единицы,
  ИНН — строки, календарные даты не сдвигаются через timezone браузера.
- ЕНС не банковский баланс. Зачтённые суммы учитываются отдельно при определении
  ещё необходимого финансирования обязательства и не создают повторное списание.
- Демонстрационный денежный план: начальный остаток + поступления − расходы
  по дням, причины дефицита и сравнение до/после импорта. Это проверка импорта
  и арифметики; обученная ML-модель, вероятность и production Core не добавляются.
- Генератор ограничен известными профилями, seed и датой среза. Произвольные
  PDF/Excel, реальные доступы, налоговый расчёт по ставкам и отправка платежей
  вне объёма.

## Этап 1 — запускаемый стенд генерации, импорта и расчёта

Статус: На ревью разработчика.
Зависимости: план явно согласован разработчиком 2026-10-24.
Результат: CLI и HTTP-заглушка с детерминированными документами, проверяемым
импортом и отчётом влияния обязательств на денежный план.

Затрагиваемые компоненты:

- `tools/mock_import/` — генератор, XML-адаптеры, нормализация, демонстрационный
  прогон и локальная HTTP-раздача;
- `tests/mock_import/` — проверки границ импорта и расчётов;
- `docs/mock-import/README.md` — запуск, форматы, ограничения и результаты;
- при необходимости точечное уточнение наших JSON Schema для выявленных
  несовпадений, с объяснением изменения; найденные внешние схемы не переписываются.

Действия:

- [x] Зафиксировать состав генерируемого набора и правила явных допущений.
- [x] Сделать генерацию документов 1С/ФНС с устойчивыми ID и манифестом.
- [x] Реализовать разбор выбранных профилей и выход в нормализованный пакет.
- [x] Обрабатывать повторы, изменившееся содержание под тем же ID, частичную
  оплату, зачтённые суммы, отсутствие срока/суммы и несовпадение компании.
- [x] Сохранить исходные документы и результат; неоднозначные записи показать
  как отклонённые/требующие уточнения, без скрытого включения в расчёт.
- [x] Выполнить дневной расчёт и сравнение до/после; вывести даты, суммы и
  связанные документы обязательных расходов.
- [x] Добавить локальную HTTP-раздачу тех же документов и описание интерфейса
  для подключения будущего импортёра.
- [x] Описать команды воспроизведения и границу между найденной схемой,
  демо-подмножеством и собственным транспортом.

Проверки:

- одинаковые seed/срез дают одинаковое содержимое и ID;
- повтор импорта не удваивает обязательства;
- конфликт содержимого под тем же ID не переписывает данные молча;
- корректны направление, точные суммы, остаток частичной оплаты и зачёт;
- отсутствующая дата, отрицательная корректировка уведомления и неизвестная
  валюта не становятся обычным положительным обязательством автоматически;
- компания/счёт не смешиваются, факт после среза не попадает во вход;
- денежный план меняется на ожидаемые суммы/даты без двойного учёта;
- HTTP возвращает сгенерированные файлы; произвольное чтение путей запрещено;
- целевые unittest, Ruff lint/format и проверка whitespace.

Критерий завершения: документированная команда воспроизводит цепочку
«генерация → импорт → обязательства → сравнение денежного плана», а проверки
подтверждают перечисленные инварианты. Процент вероятности и подключение
к настоящим базам в результатах не заявляются.

Ревью: после реализации этого единственного этапа остановка для проверки
разработчиком; без его апрува этап не считается принятым. Коммит, push,
слияние и развёртывание этим планом не разрешаются.

## Риски и открытые решения

- ED 1.25 не доказывает наличие заполненных полей в конкретной базе 1С.
- Для ЕНС известен текст формата, но нет оригинальной XSD и реального файла;
  ограниченный демо-профиль нельзя выдавать за сертифицированный импорт ФНС.
- Сумма документа, неоплаченный остаток и потребность в переводе денег на ЕНС
  имеют разный смысл; правила демонстрации должны быть явно видны.
- Подключение стенда к будущему Go Core требует отдельной реализации адаптера
  в Core; этот стенд поставляет воспроизводимые входы и ожидаемые результаты.
