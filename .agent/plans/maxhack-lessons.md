# Замечания из maxhack для переноса

Проверено 2026-10-22 по живой рабочей копии `references/maxhack`,
`.agent/instructions.md`, `.agent/instructions.local.md`, коду Gateway и указанным
в них референсам. Выводы ниже сверены с текущими файлами. Исходный HEAD maxhack:
`06e680152ea6b62ea023551498018d7e7b08d877`; в Gateway есть незакоммиченные изменения.

## Уже перенесено этим изменением

- Исходное оформление `feat: …` / `fix: …` / `chore: …` расширено типами
  `docs`, `style`, `refactor`, `perf`, `test`, `build`, `ci`, `revert` по решению
  разработчика. Правила и проверка diff/индекса перед
  публикацией — `.agent/workflows/git-conventions.md`; автокоммиты планов
  используют `feat:` с номером Issue, кратким описанием и ссылкой на исходный
  комментарий в теле по последующему решению разработчика. Нейминг веток перенесён из maxhack; автоматизация использует nickname `runner`. Команды планирования сохранены.
- Помеченные Go-референсы, проверенные пути, применимые приёмы и ограничения —
  `.agent/references/go-services.md`; подключены к локальным инструкциям и
  доверенному контексту автоматического планирования/ревью.

## Стоит принять отдельно

Ниже рекомендации для обсуждения, не принятые обязательные правила и не
разрешение реализовать инфраструктуру или менять архитектуру.

## Не переносить автоматически

MAX-бот, Kafka и отдельные сервисы прошлого продукта; OpenSpec-процесс;
корневой Go module и toolchain прошлого репозитория; чужие DTO/protobuf/миграции;
Kubernetes, cert-management и сложную observability без наших требований.
Названия папок в разных референсах различаются: это направления разделения
ответственности, а не основание массово переименовывать будущие сервисы.

Эта работа не запускала тесты maxhack и не утверждает готовность его изменённого
Gateway. Для конкретного заимствования нужно сверять текущий код и выполнять
проверки уже адаптированной реализации.
