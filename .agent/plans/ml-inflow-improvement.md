# Проверка категорий и улучшение поступлений

Статус: выполнено локально, на финальном ревью; публикация разрешена. Запрос пользователя 2026-10-23 прямо разрешает проверку,
улучшение, затем commit/push. Финальное ревью — после связанного результата.
Ветка: `god4k1ta/feat/ml_baseline`, PR #15. GBrain недоступен, Issue не назначен.

## Цель и границы

Проверить реальные назначения по категориям, исправить обнаруженные ошибки,
снизить ошибку поступлений простым прогнозом без сложной модели. Сохранить
исходные CSV, срезы, прогнозы двух baseline и денежное движение одного счёта.
REST, Go Core, консолидация и вероятность риска вне задачи. Ручная проверка
ассистентом не заменяет независимую разметку двумя людьми и не даёт population accuracy.

## Один этап — проверка, сравнение и публикация

Компоненты: `services/ml/`, исследовательский отчёт, планы, уже подготовленное
слияние main и `.gitignore`. Предыдущий эксперимент и исследование публикуются
вместе с текущим согласованным продолжением; данные и артефакты исключены.

- [x] Прочитать назначения выборки из каждой текущей категории, включая unknown;
  сохранить ручное решение и объяснение, отдельно сравнить до/после исправления.
- [x] Исправлять только явные смысловые ошибки, защищённые тестами; неоднозначные
  пополнения не выдавать за установленный перевод между счетами.
- [x] Сравнить ограниченное заранее заданное семейство прогнозов поступлений:
  профиль 4 недель, смесь профилей 4/8 недель, средний уровень 28 дней,
  недельный робастный уровень (50% среднего + 50% медианы восьми недель),
  тот же уровень с приглушённым трендом последних 4 против предыдущих 4 недель.
  Контроль — mean_90/weekday_8w. Расходы нового сравнения фиксируются как mean_90,
  чтобы оценить именно улучшение поступлений, не менять две задачи одновременно.
- [x] Выбирать вариант только на validation по WAPE суммы поступлений за горизонт,
  затем MAE остатка; development — диагностика. Показать все попробованные варианты.
  Evaluation открыть после выбора, не подбирать по пяти известным минусам.
  Весь набор ранее изучался: это диагностическая проверка, не новый holdout.
- [x] Все типы поступлений остаются в моделируемом потоке. Робастный уровень
  содержит среднее и не обнуляет редкие переводы/финансирование по их категории.
- [x] Проверить идентичность 1 232 окон и старых прогнозов, отсутствие будущих
  признаков, точные суммы, прогнозы/ошибки/тревоги, пользу и ухудшения по компаниям.
- [x] Тесты и Ruff проверены; состав commit/push подготовлен. Публикация текущей
  ветки разрешена пользователем. Финальный SHA, PR и фактический статус CI
  сообщаются по результату публикации; это не апрув и не merge PR в main.

Критерий завершения: воспроизводимый отчёт ручного разбора и сравнения,
обоснованный выбор либо честный отказ от замены при ухудшении, проходящие
проверки, опубликованный SHA без данных. Прохождение тестов не означает
апрув человека или слияние PR в main.

Риски: выборка ручного разбора целевая, категории не имеют независимого ground
truth; сезонность и крупные разовые поступления; всего пять новых разрывов в
evaluation; праздники не равны обычным выходным; новая модель не гарантирует
улучшение каждой компании или обнаружение сезонного погашения без графика.

## Уточнение после validation, до evaluation

Первые пять вариантов не превзошли mean_90 на validation. После этого проверено
расширение той же простой гипотезы на 12 недель: плоский дневной уровень из
смеси среднего и медианы недель с весами медианы 25/50/75%. Все восемь вариантов
будут показаны в отчёте, включая отклонённые. По заранее выбранному критерию
выбран `robust_12w_50`: validation WAPE суммы поступлений 21,6897% против
22,454% mean_90. Выбор зафиксирован до расчёта метрик evaluation. Расходы — mean_90.

Поздняя диагностика показала ухудшение WAPE суммы поступлений (23,36% против
22,17% mean_90), несмотря на небольшое улучшение дневной ошибки и остатка.
Поэтому статический вариант не продвигается. Следующая проверяемая гипотеза —
локальный выбор mean_90/mean_28/robust_12w_50 на трёх предыдущих 28-дневных
окнах компании. Нужно минимум два пригодных окна и снижение суммы абсолютных
ошибок минимум на 10%, иначе fallback mean_90. Внешние срезы/цели не меняются.
Все внутренние факты и признаки доступны до внешнего среза; параметры не
подбираются по пяти известным отрицательным окнам. Поздний период уже открыт,
поэтому дальнейший результат также исследовательский, не независимый тест.

Локальный выбор также ухудшил validation (23,29%), поэтому отклонён независимо
от его поздних метрик. Последняя содержательная гипотеза — годовая сезонность
операционных поступлений после проверки категорий: смесь 50/50 среднего за
90 дней и профиля того же дня недели год назад (лаг 364, окно +/- две недели),
с ростом recent90/prior90, ограниченным 0,5–2. Прочие поступления, включая свои
переводы, финансирование и unknown, сохраняют полный компонент среднего 90 дней.
При отсутствии/плохом качестве старой истории fallback mean_90 без исключения
окна. Один фиксированный вариант без перебора параметров; выбрать его можно
только при улучшении validation. Расходы остаются mean_90.
