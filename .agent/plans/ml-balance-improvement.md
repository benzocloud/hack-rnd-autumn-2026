## Цель, границы и риски

Улучшать дневной остаток и предупреждения, а не только месячную выручку.
Работа только в `services/ml/`, ML-плане/отчётах. Исходные CSV, категории старых
экспериментов, baseline, API/Go/proto/архитектура не меняются. Подробные операции,
человеческая выборка, метрики/графики остаются в игнорируемых artifacts.
Обучаемые преобразования видят только прошлое конкретного среза. ИНН — строки,
суммы — целые минимальные единицы; никаких удалений/консолидации переводов.
Нет подтверждённых будущих обязательств, календаря праздников и разметки человека.
Поздняя история уже изучалась, независимого holdout здесь нет. Мало новых минусов.

## Протокол, фиксируемый до расчёта новых результатов

- Те же 1 232 окна и неизменный frozen reference `baseline_43d7a28`.
- Все пригодные окна остаются; короткая/плохая дополнительная история даёт fallback.
- Тип поступлений по прошлым 90 дням: frequent >=45 ненулевых дней,
  sparse <=18, остальные mixed; концентрация и отрасль — дополнительные срезы.
- Фиксированные объяснимые кандидаты: раздельные операционные каналы с
  частотой/условной суммой; ожидаемое p*amount и событийное расписание;
  компактная логистическая модель наличия поступления на прошлых днях;
  строгий календарь расходов с остаточным mean_90. Только приход, только
  расходы и совместные варианты сравниваются отдельно. Старый сезонный метод
  остаётся контролем, не перенастраивается. Никаких правил для известных пяти минусов.
- Выбор по validation. Порог продвижения относительно mean_90: MAE остатка
  минимум на 5% ниже; медиана MAE компаний и средняя нормированная ошибка
  компаний не хуже; FN/FP новых минусов не выше; ошибка глубины не выше;
  не менее половины компаний без ухудшения; MAE каждого типа не хуже >10%.
  Для TP сообщать дату, заблаговременность и смещение даты, отдельно сравнивать
  общие обнаруженные случаи. При отсутствии TP метрики не заменять нулями.
  Среди прошедших — минимум MAE, затем FP, FN, имя. Если никто не прошёл,
  retain mean_90. Поздние результаты не участвуют в выборе.
- Promotion default требует тех же ворот на поздней диагностике и последующей
  независимой проверки на новых данных. В этом цикле без новых данных default
  остаётся прежним даже при исследовательском улучшении.
- Ожидаемый/осторожный сценарии оцениваются раздельно. Осторожный использует
  меньшие/поздние неопределённые приходы и верхний прошлый уровень расходов;
  не является вероятностью или доверительным интервалом.
