# Общий диалог Issue и связанных PR

Цель: каждый новый запрос получает опубликованную историю одной задачи и её
связанных PR; создание плана передаёт задачу в PR и закрывает Issue после ссылки.
Основание: принятый ADR-021 и поручение разработчика «приступай».

Исходное состояние: `/question` и обычный `/discuss` читали исходное обсуждение
и непосредственно упомянутые Issues. Соседние PR не собираются. Создание плана
публикует ссылку, но не закрывает Issue. Обработчик планов требует открытый Issue.
PR #12 слит в `main` как `12b8ff9`; соответствующий обработчик больших планов
установлен на runner, 90 тестов и проверка от непривилегированного пользователя
прошли. GBrain недоступен.

Границы: текущие команды, GitHub REST API и существующий SSH-протокол.
Issue является корнем; PR получает корень только из формальной ссылки в своём
описании (`Refs`, `Closes`, `Fixes`, `Resolves` либо метка управляемого плана).
Несколько разных корней считаются неоднозначностью. Обычное упоминание в
комментарии остаётся контекстом и не объединяет диалоги. Связанные PR ищутся
по timeline Issue с повторной проверкой их текущих описаний и репозитория.
Закрытые задачи и PR учитываются как история; ответ остаётся у исходной команды.

Без БД, постоянной модельной сессии, новых зависимостей и расширения прав модели.
Вне скоупа: GBrain, Fadwix, защита main, исправление ссылок на отсутствующие файлы,
автоматическая реализация задач ботом, апрувы, push, слияние и установка.
Первоначально каждый этап требовал остановки для апрува. Последующим прямым
поручением разработчик разрешил мультиагентное ревью, исправление замечаний,
коммиты проверенной реализации и переход к следующему этапу без подтверждения.
Итоговый результат этапов 2–3 остаётся на ревью до апрува разработчика.

## Этап 1 — общий контекст вопросов и обсуждений

Статус: Принят. Разработчик одобрил результат командой «апрув дальше».
Зависимости: нет; существующий транспорт и формат контекста.
Результат: `/question` и обычный `/discuss` видят Issue и все явно связанные
PR, включая закрытые; сохраняют авторов, даты, ревью и ответы к строкам.
Файлы: `.agent/infra/runner/github_dialogue.py`,
`.agent/infra/conversation/github_conversation.py`,
`.agent/infra/conversation/conversation_policy.py`,
`.agent/infra/conversation/ssh_conversation.py`,
`.agent/infra/tests/test_dialogue.py`, `.agent/infra/tests/test_conversation.py`,
`.agent/infra/README.md`, `.agent/plans/pre-hackathon-rollout.md`,
`.agent/decisions.md` (сведения о выполненной установке).

Действия:
- [x] Добавить общий сборщик формальных связей и истории PR без рекурсивного
  обхода упоминаний, с полной пагинацией и явными ограничениями.
- [x] Подключить его к сбору контекста, подбору исходников вопроса и повторной
  проверке перед ответом; сохранить текущий SHA запроса и место ответа.
- [x] Актуализировать сведения об уже выполненной установке и оставшейся работе.

Предлагаемые проверки: корневой Issue, обычный PR и PR без Issue; закрытые
связанные объекты, неоднозначные ссылки, чужой репозиторий, упоминания в
комментариях, добавленные/удалённые PR, изменение истории во время ответа,
ошибки API/пагинации и лимиты; проверка реально переданного модели запроса.
Все GitHub/SSH/модельные вызовы в тестах заменить заглушками. Ruff и полный
набор инфраструктурных тестов. Критерий: полная история передана без скрытого
усечения, устаревший ответ отклонён, прежняя авторизация и права сохранены.

Результат: реализованы `dialogue_root` и `related_prs`, полная история связанных
PR без повторного включения исходного PR. Автор, даты, состояние ревью и позиции
ответов сохранены; ссылки в ответе показывают корневой Issue и учтённые PR.
Комментарии соседних PR участвуют в подборе исходников `/question`. Повторный
сбор перед публикацией отклоняет изменённую историю, новые/удалённые связи и SHA.

После ревью воспроизведён и исправлен разбор ссылок с двоеточием:
`Closes: #7` сохраняет общий диалог, а `Refs #7` вместе с `Closes: #8`
отклоняется как неоднозначность. Проверены ссылки исходного и соседнего PR,
служебная метка, URL и списки Issues; прежние формы без двоеточия сохранены.

Выполнено: все 104 инфраструктурных теста, `ruff check .`,
`ruff format --check .`, `git diff --check`. Из них 14 новых тестов проверяют
связи, пагинацию, историю и фактическую передачу контекста модели через заглушку.
Обращения к модели и SSH в проверках заменены заглушками. Через Context7 изучен
контракт API, а существующий timeline Issue #8 проверен только на чтение.
Новые комментарии и задачи не публиковались, runner и Fadwix не изменялись.
Изменения локальные; обновление обработчиков потребует согласованной установки.
После ревью получен апрув разработчика; разрешён переход к этапу 2.

## Этап 2 — общий контекст планирования и ревью

Статус: На ревью.
Зависимость: принят этап 1.
Результат: планирование и `/agent-review` используют тот же сборщик;
изменение плана в открытом PR допускается при закрытом корневом Issue.
Компоненты: `.agent/infra/planning/`, `.agent/infra/review/`, их тесты,
общие сравнение истории и валидация в `runner/github_dialogue.py` и
`review/review_policy.py`, использующие их обработчики `conversation/`,
`.agent/workflows/issue-planning.md`, `.agent/workflows/automated-review.md`
и документация инфраструктуры.

Действия:
- [x] Подключить историю к планированию и ревью с проверкой актуальности.
- [x] Сохранить запрет новых команд в закрытых обсуждениях; разрешить чтение
  закрытого корня при запросе из открытого связанного PR.
- [x] Сохранить ограничение изменения только файла плана и явный запуск ревью.

Предлагаемые проверки: план и ревью учитывают соседние PR и закрытый Issue;
изменение корня, исходников или истории блокирует публикацию; вопрос и обычное
обсуждение не получают права записи. Полный набор тестов, Ruff и actionlint
при изменении workflow. Критерий: единые связи для всех анализирующих команд,
без расширения прав или повторного вызова модели из-за тестов/обычного push.

Результат: оценка Issue, создание/правка плана и `/agent-review` используют
общий сборщик связанных PR. Модель получает авторов, даты, закрытые обсуждения,
ревью и ответы к строкам; ссылки на код остаются привязаны к SHA запроса.
Перед записью плана или итогового ревью история собирается заново; изменения
задачи, описания, комментариев, источников или состава PR блокируют результат.
Ошибки сбора обновляют исходный статус; реакции и метаданные отображения
не считаются изменением истории. План может быть изменён из открытого
управляемого PR при закрытом корневом Issue. `/create-plan` в закрытом Issue
и правка через закрытый PR по-прежнему запрещены. История не даёт новых апрувов.

Проверено: все 113 инфраструктурных тестов, Ruff lint/format и проверка пробелов.
Девять новых тестов этапа проверяют цикл обработчиков планирования с закрытым
Issue, передачу истории worker ревью, устаревание, отказ API и лимит контекста
до вызова модели. Реальные GitHub, SSH и модель в этих тестах заменены заглушками.
Workflow YAML не менялся. Общая валидация и сравнение истории переиспользуются
всеми обработчиками; лимит контекста 160 000 символов проверяется без усечения.
Проверки состояния и прав, фиксированного файла плана, сохранённого состояния,
SHA, навыков и публикации одного комментария сохранены.

Мультиагентное ревью этапов 1–2: `caveman-review` подтвердил потерю связей для
квалифицированных ссылок `REPOSITORY#N`; добавлены их разбор и регрессии корня,
неоднозначности и соседнего PR. `ponytail-review` нашёл повторную проверку
списков истории; дублирование удалено, общая валидация сохранена. После
исправлений все 113 тестов, Ruff и проверка пробелов прошли. Разработчик
разрешил коммит и продолжение без промежуточного подтверждения. Это разрешение
не означает итоговый апрув реализации, push, merge или установку.

## Этап 3 — передача Issue в PR с планом

Статус: На ревью.
Зависимость: этап 2 прошёл мультиагентное ревью и сохранён коммитом `ba8ea4b`;
разработчик прямо разрешил продолжение без промежуточного подтверждения.
Результат: успешный `/create-plan` публикует ссылку на существующий либо новый
плановый PR и только после успешной публикации закрывает Issue.
Компоненты: `.agent/infra/planning/github_plan.py`, тесты жизненного цикла,
документация и план последующей согласованной установки.

Действия:
- [x] Добавить упорядоченную и повторяемую передачу без дубликатов PR/веток.
- [x] При ошибке публикации ссылки оставить Issue открытым; при ошибке закрытия
  сохранить созданный PR и ссылку, не выдавать ложное подтверждение.
- [x] Зафиксировать ограничения, проверенные результаты и порядок rollout.

Предлагаемые проверки: создание, повторный запрос, ошибка создания/ссылки/
закрытия и повтор после частичного успеха; полный цикл с заглушками; Ruff,
инфраструктурные тесты и проверка пробелов. Критерий: Issue закрывается только
после доступного PR и ссылки; закрытие не означает готовность исправления.

Результат: `handoff_plan` проверяет открытый managed plan-only PR и непустой
фиксированный файл по head SHA, публикует либо восстанавливает точную ссылку
в одном комментарии, повторно проверяет PR/Issue и только затем закрывает Issue.
Путь повторного `/create-plan` для уже созданного PR работает без нового
результата модели, коммита, ветки или PR; соответствующее условие Actions
публикует передачу даже при пропущенном inference. Права publisher не расширены.

Мультиагентное ревью: `caveman-review` подтвердил случай удалённого/отсутствующего/
пустого плана; он исправлен и проверен до любых записей передачи. Повторная
проверка агента не нашла новых ошибок. `ponytail-review`: лишней сложности нет.
Дополнительно исправлена проверка точной Markdown-ссылки, чтобы ссылка на PR
с номером `100` не подменяла ожидаемую ссылку на `10`.

Выполнено: 124 инфраструктурных теста, Ruff lint/format, actionlint для
изменённого workflow, проверка пробелов. Одиннадцать новых тестов проверяют
порядок записей, ошибки создания/ссылки/закрытия и повтор, отсутствие/удаление/
пустой план, закрытые и смешанные PR, изменение задачи/PR после ссылки,
восстановление ссылки, дубликаты статусов и отозванные права. Реальные модель,
GitHub и SSH в тестах заменены заглушками; квота модели не расходовалась.

Сохранено прежнее ограничение: ошибка создания PR после создания ветки может
оставить ветку без PR. При отсутствии managed PR повтор не перезаписывает
ветку; требуется ручное восстановление. Автоматический повтор без модели
реализован для случая, когда PR уже существует. Это явно проверено тестом.

Подготовлен порядок согласованного rollout в `.agent/infra/README.md`.
Разрешение на коммит получено напрямую; push, merge и установка не выполнялись.
Runner и Fadwix не изменены. Этапы 2–3 ожидают итогового ревью разработчиком;
прохождение проверок и агентского ревью не означает их принятие.

Риски: timeline содержит случайные упоминания и устаревшие связи; проверять
актуальное описание каждого кандидата. Полная история может превышать текущие
лимиты — завершать запрос явной ошибкой, не сокращать молча. Одновременные
изменения обсуждения делают ответ устаревшим. Живые проверки требуют отдельного
согласованного запуска и расходуют квоту; здесь они не считаются выполненными.

Контракт API проверен через Context7 по официальной документации
[timeline](https://docs.github.com/en/rest/issues/timeline) и
[cross-referenced](https://docs.github.com/en/rest/using-the-rest-api/issue-event-types).
