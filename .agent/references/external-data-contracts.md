# Внешние форматы 1С, ФНС и учётных систем: результаты поиска

Проверено: **2026-10-23**, фиксация источников `20:23:52 UTC`.
Статус: исследовательская поставка этапа 1A **на ревью**, без реализации
интеграций. Выбор первого источника и его объёма разработчиком ещё не утверждён.

## 1. Результат и граница достоверности

Найдены и прочитаны настоящие опубликованные схемы/спецификации, а не только
наши ранее составленные DTO:

| Материал | Что фактически доступно | Как использовать |
| --- | --- | --- |
| 1С EnterpriseData **1.25** | Официальный скачанный архив и XSD, проверенные имена типов/полей | Этапы оплаты заказа, заявки на расход, банковские факты |
| 1С ClientBankExchange **1.03** | Официальная HTML-спецификация прочитана | Импорт исполненных банковских движений/остатков |
| ФНС, уведомление **1110355**, формат **5.03** | Скачана публичная копия XSD из закреплённого коммита RuOdoo | Налоговые суммы и периоды; прямого срока оплаты нет |
| ФНС, справка ЕНС **1160082**, формат **5.03** | Прочитано опубликованное описание XML из текста приказа в правовой базе; оригинальная XSD не скачана | Налоговые сведения, отдельные сроки, зачтённые суммы; требуется дополнительная проверка файла |
| МойСклад JSON API **1.2** | Прочитаны исходники официальной документации и разобран опубликованный JSON-пример | Счета, плановая дата, сумма и показатель оплат |
| Saby, карточки форм и запрос ИОН | Прочитаны страницы самого оператора | Проверка назначения форм, способов получения и ограничений; не SDK/API-спецификация |

Ссылки, SHA-256 скачанных оригиналов, версии и ограничения находятся в
[sources.json](external-data-examples/sources.json). Примеры ниже — извлечённые
схемы или проекция опубликованного примера поставщика, **без выдуманных значений**.
Реальные документы конкретного налогоплательщика не получены. Анонимный публичный
API получения его будущих налогов по одному ИНН не подтверждён.

Context7 в сессии отсутствует. GBrain отключён/недоступен. Источники — веб,
первичные файлы поставщиков и обозначенные копии документов; вход в чужие
компании и запросы к финансовым API с учётными данными не выполнялись.

## 2. 1С: EnterpriseData 1.25

Первоисточники:

- [Таблица версий и ссылка на архив](https://its.1c.ru/db/content/metod8dev/src/developers/dataexchange/enterprisedata/i8105934.htm).
- [Официальный архив XSD/описаний](https://its.1c.ru/db/files/1CITS/EXE/EnterpriseDataFiles/EnterpriseDataFiles.zip).

Из архива прочитан `EnterpriseDataFiles/XSDschemeEntepriseData1_25.zip`, внутри —
`XSDschemeEntepriseData1_25.xsd`. Пространство имён:
`http://v8.1c.ru/edi/edi_stnd/EnterpriseData/1.25`.
Это подтверждённая версия **формата**, не версия конкретной установленной УНФ/БП.

[Извлечённые определения](external-data-examples/1c-enterprisedata-1.25.fragments.txt)
содержат следующие настоящие поля:

| Тип XSD | Поля | Тип/обязательность |
| --- | --- | --- |
| `Документ.ЗаказКлиента.ЭтапыОплаты.Строка` | `ДатаПлатежа`, `СуммаПлатежа` | `xs:date`, `tns:ТипСумма`; оба обязательны внутри строки |
| Тот же тип | `ИдентификаторСтроки`, `НомерСтрокиДокумента` | Необязательны |
| `ОбщиеСвойстваЗаявокНаОперацииСДС` | `Сумма`, `Валюта` | Обязательны |
| Тот же тип | `КрайнийСрокПлатежа`, `УтвержденнаяДатаПлатежа` | Необязательные `xs:date` |
| `ОбщиеСвойстваПБДС` | `ДатаВыписки`, `Сумма`, `Валюта` | `xs:date`, `tns:ТипСумма`, ссылка на валюту |
| Ключевые свойства банковского документа | `Дата` | `xs:dateTime`; отдельна от даты выписки |
| `ТипСумма` | Ограничения | `xs:decimal`, `totalDigits=15`, `fractionDigits=2` |

Точное имя важно: в схеме `ДатаПлатежа`, а не придуманное `payment_date`.
`xs:date` даёт календарную дату вида `YYYY-MM-DD`; `xs:dateTime` — форму
с `T`. Наличие timezone определяется самим значением, его нельзя молча заменить
на UTC. Ссылку `Валюта` нужно разрешить отдельно.

Схемы проверены как XML. Полная валидация реального сообщения, поддержка данной
версии конкретной конфигурацией и доступность заполненных этапов не проверялись.
Остаток оплаты не выводится из одной суммы этапа без сверки исполнения.

## 3. 1С: банковский обмен 1.03

[Официальная спецификация](https://v8.1c.ru/tekhnologii/obmen-dannymi-i-integratsiya/standarty-i-formaty/standart-obmena-s-sistemami-klient-banka/formaty-obmena/)
описывает текстовый `1CClientBankExchange`:

| Поле | Подтверждённый смысл |
| --- | --- |
| `ВерсияФормата` | На странице — `1.03` |
| `Кодировка` | Варианты `DOS` / `Windows` |
| `Дата` | Дата документа, `дд.мм.гггг` |
| `ДатаСписано`, `ДатаПоступило` | Даты исполнения, `дд.мм.гггг` |
| `Сумма` | Рубли с необязательной копеечной частью |
| `НачальныйОстаток`, `КонечныйОстаток` | Остатки соответствующего раздела счёта/периода |

Банковский факт определяется по исполнению и выбранному счёту. Дату документа
нельзя автоматически считать датой движения. `СрокПлатежа` в этой спецификации
описывает аккредитив и не является общим сроком любого счёта поставщика.
Номер документа не гарантирует глобальную уникальность.

## 4. ФНС: налоговое уведомление 1110355, 5.03

- [Официальная карточка приказа 02.11.2022 № ЕД-7-8/1047@](https://www.nalog.gov.ru/rn77/about_fts/docs/12964598/) найдена; прямое чтение вернуло **403**.
- [Скачанная публичная XSD-копия, закреплённый коммит RuOdoo](https://git.ruodoo.ru/ruodoo-public/public/raw/commit/dd10b7dde5935d4da35943e7ec9a26d169b9bee6/rsbu_fns_reporting/data/schemas/UT_UVISCHSUMNAL_1_263_00_05_03_01.xsd).
- [Карточка формата оператора Saby](https://formats.saby.ru/report/fns/128513).

Локально сохранены [исходные байты XSD](external-data-examples/UT_UVISCHSUMNAL_1_263_00_05_03_01.xsd)
и [фрагменты](external-data-examples/fns-notification-5.03.fragments.txt).
Исходные CRLF и bytes сохранены, SHA-256 совпадает с реестром sources.json.
Точечный `.gitattributes` отмечает CRLF этого vendor-файла допустимыми при
whitespace-проверке; вырезки в `.fragments.txt` нормализованы без изменения текста.
Кодировка файла — `windows-1251`, ограничение `ВерсФорм` — `5.03`, КНД — `1110355`.
Это копия из репозитория поставщика ПО; её побайтовая идентичность текущему
файлу на ФНС не установлена.

| Узел/атрибут | Что подтверждено скачанной схемой |
| --- | --- |
| `Документ/@ДатаДок` | Обязательный `ДатаТип`: `ДД.ММ.ГГГГ` |
| `УвИсчСумНалог` | Повторяемая структура налоговых сумм |
| `@СумНалогАванс` | Обязательный `xs:decimal`, 17 цифр, до 2 дробных |
| `@Период` | Коды `21`, `31`, `33`, `34` |
| `@НомерМесКварт` | Код месяца/квартала; не календарная дата |
| `@Год` | `xs:gYear` |
| `@КБК`, `@ОКТМО`, `@КППДекл` | Классификаторы/реквизиты, сохраняются строками |

Уведомление направляет **налогоплательщик** в ФНС. Это не ответ ФНС со списком
будущих оплат. В проверенном типе отсутствует прямой срок платежа; нижней
границы ноль для суммы нет. Поэтому сумму нельзя без проверки трактовать как
новый положительный платёж: корректировка требует своей логики.
Срок из налогового периода автоматически не вычислялся.

## 5. ФНС: справка ЕНС 1160082, 5.03

- [Официальная карточка приказа 05.11.2024 № ЕД-7-8/987@](https://www.nalog.gov.ru/rn77/about_fts/docs/15527368/) — **403** при прямом чтении.
- [Прочитанная копия текста приказа с приложением 2](https://legalacts.ru/doc/prikaz-fns-rossii-ot-05112024-n-ed-7-8987-ob-utverzhdenii/).
- [Сверка назначения и версии у оператора Saby](https://formats.saby.ru/report/fns/131042).

Описание называет XSD `IU_SPKRO_1_875_01_05_03_xx`; сам файл не скачан.
В [извлечении таблиц](external-data-examples/fns-ens-5.03.format-table-extract.txt)
подтверждены:

- `ДатаСостСпр`, `ВремяСостСпр`, `СальдоЕНС`;
- путь `Документ/ИнфПрОбязЗачт/ПредОбяз/ИнфПредНачисл`;
- атрибуты строки `СрокУплат`, `Сумма`, `СумЗачтОбяз`, `КБК`, `ОКТМО`, `КПП`.

В таблице 4.22 `СрокУплат` необязателен, формат `ДД.ММ.ГГГГ`;
две суммы обязательны, `N(17.2)`, рубли. Наличие раздела/даты у конкретного
налогоплательщика не гарантируется. ЕНС не банковский остаток; уже зачтённые
средства нельзя вновь объявить будущим банковским списанием. Без оригинального
XML/XSD совместимость парсера не заявляется.

## 6. МойСклад и Saby как дополнительные источники

Официальный [репозиторий документации МойСклад](https://github.com/moysklad/api-remap-1.2-doc)
описывает `master` как документацию продуктового сервера. Прочитан закреплённый
коммит `1d769672f9b1d053805f4e4ee06034b0398bf251`, а не ветка `pre_release`.

- [Счёт покупателю](https://github.com/moysklad/api-remap-1.2-doc/blob/1d769672f9b1d053805f4e4ee06034b0398bf251/md/documents/_invoice_out.md).
- [Счёт поставщика](https://github.com/moysklad/api-remap-1.2-doc/blob/1d769672f9b1d053805f4e4ee06034b0398bf251/md/documents/_invoice_in.md).
- [Общие правила](https://github.com/moysklad/api-remap-1.2-doc/blob/1d769672f9b1d053805f4e4ee06034b0398bf251/md/_general.md).

Подтверждены `id`, `sum`, `payedSum`, необязательный `paymentPlannedMoment`,
`rate`, `updated`, `applicable`. Сохранена [проекция JSON-примера поставщика](external-data-examples/moysklad-invoiceout.vendor-example.projection.json):
значения не менялись; это не живой ответ и не полный объект.
Объявленный тип сумм — `Float`; точный масштаб именно `sum`/`payedSum` по
просмотренным определениям не подтверждён достаточно явно. Автоматическое
умножение на 100 для этих полей **не зафиксировано**.

Общие правила подтверждают даты `YYYY-MM-DD HH:mm:ss[.SSS]`, MSK для времени
создания/обновления, отсутствие незаполненных необязательных полей, пагинацию
`limit/offset` до 1000 и Basic/Bearer-аутентификацию. Фильтр `updated` не является
доказательством полного исторического состояния на произвольную дату.

Saby публикует [описание запроса ИОН](https://formats.saby.ru/report/fns/130940)
с вариантами форматов ответа, включая XML; это путь получения документов
через налоговую отчётность. Идентификаторы/поля собственного интеграционного
API Saby в этой работе не установлены. Их нельзя заменить придуманным
`GET /fns/payments` и выдать за контракт поставщика.

## 7. Mapping к нашему входу: подтверждения и пробелы

| Источник | Кандидат на нормализованное поле | Ограничение |
| --- | --- | --- |
| ED 1.25: этап `ДатаПлатежа` | `scheduled_date` | Дата конкретного этапа, не дата всего документа |
| ED: `СуммаПлатежа`, ссылка `Валюта` | `amount` | Валюта разрешается отдельно; общая сумма не доказывает неоплаченный остаток |
| ED: `ИдентификаторСтроки` | Часть внешней идентичности ожидания | Поле необязательно; нужен ID документа и проверка устойчивости |
| ED: заявка, утверждённая дата/крайний срок | Даты планирования и ограничения | Оба поля могут отсутствовать; нельзя молча выбрать одну семантику |
| ClientBank: даты исполнения, сумма | Историческая `Transaction` | Сторона и выбранный счёт определяют направление |
| ФНС 1110355: сумма/КБК/период | Налоговое свидетельство для проверки | Не готовый `Payment`: нет подтверждённых даты и остатка |
| ФНС 1160082: строка предстоящего начисления | Кандидат на ожидание после сверки | Дата необязательна, учесть зачёт/ЕНП; устойчивый ID строки не установлен |
| МойСклад: `paymentPlannedMoment`, `sum`, `payedSum` | Ожидание после уточнения единиц и правил оплат | Проверить валюту, проведение, переплату, удаления и отсутствие даты |

Общего внешнего DTO нет: адаптеры должны сначала сохранить оригинальные
значения/версию/источник. Прежние `docs/data-contracts/*.schema.json` описывают
**нашу** нормализацию и не подтверждают совместимость с перечисленными системами.

## 8. Как преобразовывать даты

Это предлагаемые правила нашего адаптера на основе проверенных типов:

| Источник | Вход | Правило адаптера |
| --- | --- | --- |
| ClientBank, даты исполнения | `DD.MM.YYYY` | Строго разобрать дату и вывести `YYYY-MM-DD` |
| ED, `ДатаПлатежа` | `xs:date` | Сохранить календарную дату, не сдвигать временем браузера |
| ED, дата документа | `xs:dateTime` | Сохранить исходное время/offset; отсутствие offset требует явной политики |
| ФНС, `ДатаДок`/`СрокУплат` | `ДД.ММ.ГГГГ` | Строго разобрать дату; отсутствие срока оставить отсутствием |
| ФНС, период/год | Коды + `xs:gYear` | Сохранить отдельно; не выдавать код за дату оплаты |
| МойСклад | Дата и время с пробелом, без `Z` | Различать деловую дату и момент; не дописывать `Z` к исходной строке |

Ошибки разбора, неизвестные единицы/валюта и отсутствующие обязательные для
нашего расчёта сведения показываются пользователю. Налоговый календарь,
привязка timezone и выбор даты из нескольких полей — отдельные правила,
а не свойства, автоматически доказанные названием формата.

## 9. Рекомендация для следующего согласования

Для первого дополнительного источника **предлагается** ED 1.25: этапы оплаты
заказа/заявки на расход. Основание — скачанная официальная схема с датой и суммой;
нужны экспорт конкретной конфигурации и проверка исполнения/идентичности.

Если приоритет именно ФНС — выбрать справку 1160082 и сначала получить законно
выгруженный обезличенный XML с разделом предстоящих начислений и оригинальную XSD.
Уведомление 1110355 полезно для структуры суммы/периода, но само не закрывает
ввод датированных обязательств.

Граница будущего мока: локальная демонстрация выбранного формата/среза,
повторы, отсутствие даты/раздела, частичное исполнение и обновление состояния.
Любые значения для мока будут отдельно обозначены синтетическими. Эндпоинт
такого мока будет нашим, не объявленным API ФНС/1С. Сервер/адаптер сейчас
не создавались. Файловая история → preview дополнительных ожиданий → явное
применение → новый прогноз — предлагаемый демо-путь, не выполненный тест.

## 10. Skeptic pass и выполненные проверки

- Скачаны официальные архивы ED 1.0.1 и текущего набора с 1.25; в выводах
  о будущих платежах использована именно 1.25. Старая обзорная страница 1С
  с 1.0.1 не выдаётся за актуальную спецификацию.
- Проверены имена, обязательность и типы по XSD, а не по поисковым сниппетам.
- Оригинальные FNS-карточки недоступны: источник копии и отсутствие проверки
  тождества явно обозначены. У 1160082 получено описание, не XSD.
- Версии из Saby, юридических копий и фактически скачанной схемы различаются
  по роли; совпадение номера не доказывает текущую редакцию каждого приложения.
- МойСклад закреплён на коммите; выбран действительный JSON-пример. Момент
  `updated` в примере позже плановой даты — пример не доказывает историческую
  доступность сведений на дату планируемого платежа.
- По опубликованным данным не проверены реальные доступы, API-вызовы,
  все ограничения конфигураций, валютный mapping и банковская платёжеспособность.
- Текущие версии в конкретной установке и актуальность приказов перед production
  требуют отдельной сверки; этот отчёт не налоговая инструкция.

Ни новые поля поставщиков, ни реальные документы клиентов не сочинялись.
